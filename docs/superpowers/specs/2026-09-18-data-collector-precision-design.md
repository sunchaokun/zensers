# 2026-09-18-data-collector-precision-design.md

## Context
数据分析链路已通过 prompt 优化将契约分从 12.5 提升至 87.5（P0 fail 0）。下一步聚焦**数据搜集 Agent**，从源头提升证据精准度与可追溯性，为分析和报告层提供更高质量输入。

核心问题不是"过滤来源"（会损害新兴行业召回），而是：
1. 关键词派生不够精准 → 搜到跑题数据
2. 同一 metric 多口径/多年份冲突无标记 → 分析层无法判断
3. 证据强度不可见 → Agent 无法区分强/弱证据

## 设计原则
- **不硬过滤**：不按来源 tier 删除数据，只打分/标记
- **跨行业通用**：传统行业（tier1 多）和新兴行业（tier1 少）都能正常工作
- **可回放验证**：每步改动用历史样本对比，确保不回归
- **渐进式**：三个模块独立，可分别验证后再组合

## 三个模块

### Module 1: 关键词派生（Keyword Derivation）
**目标**：让搜索查询更精准，减少跑题数据

**实现思路**：
- 输入：研究主题（topic + aspect）
- 输出：核心词 + 口径词 + 时间词 + 对比词 + 排除词
- 例：`中国智能手机市场 增长趋势` →
  - 核心词：`智能手机 出货量 市场规模`
  - 口径词：`出货量 零售量 激活量 ASP`
  - 时间词：`2025 2026 Q1 Q2 同比`
  - 排除词：`猪肉 新能源汽车`（跨行业噪音）

**验证指标**：
- 跑题 data_point 比例下降（当前基线待测）
- 有效证据覆盖率不降

### Module 2: 口径一致性校验（Caliber Consistency Check）
**目标**：标记冲突数据，而非删除

**实现思路**：
- 按 metric 分组，检测同一 metric 下不同口径/年份/地域
- 冲突数据打 `conflict_flag` + `conflict_reason`
- 冲突记录传递给分析层，由 Agent 决定采信

**验证指标**：
- 冲突检测率（人工抽查）
- 分析层对冲突数据的处理质量

### Module 3: 证据强度标签（Evidence Strength Labeling）
**目标**：让 Agent 知道每条证据的可信度

**实现思路**：
- 每条 data_point 增加 `evidence_strength` 字段：
  - `strong`：tier1/2 来源 + 口径完整 + 时间匹配
  - `moderate`：tier3 来源或口径/时间部分缺失
  - `weak`：tier4 来源或口径/时间严重缺失
- 打分逻辑透明，可审计

**验证指标**：
- 标签分布合理性
- Agent 对 weak 证据的处理是否更谨慎

## 执行顺序
1. 先实现 Module 1（关键词派生），独立验证
2. 再实现 Module 2（口径校验），独立验证
3. 最后实现 Module 3（证据强度），与前两个组合验证
4. 全部完成后，跑完整回放（smartphone + pork）对比基线

## 验证方法
- 使用 `run_round.py --skip-llm` 验证数据结构变化
- 使用完整 LLM 评分验证分析质量
- 对比 round7/round8 基线

## 风险与回滚
- 风险：关键词扩展过度导致召回噪音增加
  - 缓解：排除词表 + 回放验证
- 风险：口径校验误标
  - 缓解：标记而非删除，Agent 有最终决定权
- 回滚：每个模块独立，可单独回滚
