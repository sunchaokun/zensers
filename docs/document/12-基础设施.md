### 1.2 写前日志 (WAL)

确保数据操作的原子性和可恢复性：

```
操作请求 → WAL 记录 → 实际执行 → WAL 标记完成
                │
                └── 崩溃恢复：重放未完成的 WAL 记录
```

### 2.2 用户会话管理 (SessionManager)

**文件**: `src/core/session_manager.py` (511 行)

全局会话管理器，替代 `research_api.py` 中原始的 `_sessions` 全局字典。每次修改自动持久化到磁盘，服务重启后自动恢复。

#### 核心机制

| 机制 | 实现 | 说明 |
|------|------|------|
| 自动持久化 | `PersistentSessionDict.__setitem__` → `_save_to_disk()` | 每次写入自动触发，无需手动 `flush()` |
| 原子写入 | `.tmp` 临时文件 → `os.replace()` 重命名 | 防写中断导致文件损坏 |
| 防截断守卫 | `__setitem__` 检查 `conversation_history` 是否 Append-only | 阻止任何尝试缩短历史的操作 |
| 写去抖 | `_debounce_ms=2000`，同一 session 2 秒内不重复写 | 高频更新时保护磁盘 IO |
| 自动备份 | `_save_backup()` 在守卫触发前保存时间戳备份 | 备份文件: `{id}.{timestamp}.guard.bak` |
| 延迟加载 | `get()` 内存未命中时从磁盘加载 | 启动时只预加载最新的 5 个 session |
| 崩溃恢复 | `recover_all()` 启动时扫描 `data/sessions/*.json` | 清理残留 `.tmp` 文件，按 mtime 倒序加载 |
| 过期清理 | `cleanup_expired(max_age_hours=72)` | 仅清理状态为 COMPLETED/CANCELLED 的旧 session |

#### PersistentSessionDict

```python
session["key"] = value    # 触发自动持久化
session["conversation_history"] = new_list  # 若短于现有 → 抛出 ValueError
session.update({...})      # 批量更新，同样受防截断守卫
session.pop("key")         # 删除后自动持久化
```

每次 `__setitem__` 同时同步 `display_history`（使用 `dict.__setitem__` 规避循环触发），确保 UI 显示的完整历史不受压缩影响。

#### 序列化

- `_serialize_value()`: 递归处理 `datetime`、`Enum`、`dataclass`、`to_dict()` 等类型
- `_transient_fields`: `{"clarifier", "_lock", "_pending_v2_revision"}` 跳过持久化
- `_deserialize_state_machine()`: 从 dict 恢复 `ConversationStateMachine` 实例

#### 存储位置

```
data/sessions/{session_id}.json        # 主文件
data/sessions/{id}.{timestamp}.bak     # 时间戳备份
data/sessions/{session_id}.tmp         # 原子写入临时文件（残留即表明上次写被中断）
```

### 2.3 会话持久流 (SessionStreamer)

详细文档见 [`15-会话持久流.md`](15-会话持久流.md)，本节仅摘要关键设计点。

**文件**: `src/core/session_streamer.py` (454 行)

SessionStreamer 是**会话级 SSE 持久流**，与任务级的 `ProgressStreamer` 构成双流架构：

```
前端
├── EventSource /api/v1/stream/{task_id}            ← ProgressStreamer (任务完成后终止)
└── EventSource /api/v1/session-stream/{session_id}  ← SessionStreamer (会话级，永不终止)
```

核心特性：

- **10 种事件类型**：chat_response / chat_token / chat_thinking / agent_message / heartbeat / connected / quality_result / section_quality / preview_refresh / quality_confirmed
- **类级别订阅者模式**：`_subscribers[session_id] → Set[asyncio.Queue]`
- **重放恢复**：内存缓冲 20 条 + SessionManager 持久化 100 条
- **双写持久化**：chat_response 和 agent_message 同时写入 conversation_history
- **Token 流绕过缓冲**：chat_token / chat_thinking 不进入 replay buffer
- **Agent 消息节流**：200ms 间隔
- **85 处跨模块调用**：覆盖 GenericAgent、Execution Engine、Orchestrator、Research API（31 处）、Research Executor、质量检查 Agent、进度心跳等

### 2.4 Agent 会话层级管理

**文件**: `src/core/agents/agent_session.py` (605 行)、`session_persistence.py` (353 行)

解决四个架构缺陷：
1. Agent 创建后没有独立 Session
2. 无法追踪父子 Session 关系
3. 主控无法知道子 Agent 执行进度
4. 无法实现事件驱动的结果聚合
5. Phase 3.10 新增：Session 持久化与崩溃恢复

#### AgentSession (dataclass)

| 字段 | 类型 | 说明 |
|------|------|------|
| `session_id` | str | 唯一标识 (`session_{8位hex}`) |
| `agent_id` | str | 关联的 Agent ID |
| `parent_session_id` | Optional[str] | 父 Session ID |
| `origin` | SessionOrigin | PRIMARY(直接创建)/SPAWNED(子)/BACKGROUND(后台) |
| `status` | AgentSessionStatus | PENDING→RUNNING→COMPLETED/FAILED/CANCELLED |
| `progress` | float | 0.0-1.0 |
| `checkpoint_data` | Optional[Dict] | 检查点数据（崩溃恢复用） |
| `agent_template` | Optional[Dict] | hibernate 恢复用 |

状态机：
```
PENDING ──start()──▶ RUNNING ──complete()──▶ COMPLETED
                         ├──fail()──────▶ FAILED
                         ├──cancel()────▶ CANCELLED
                         └──hibernate──▶ HIBERNATED ──resume()──▶ RESUMING ──▶ RUNNING
```

#### AgentSessionRegistry

追踪主控 Session 下的所有子 Agent Session：

- `register(session)` — 注册子 Session，设置 parent_session_id
- `get_by_agent(agent_id)` — 根据 Agent ID 查找
- `update_status()` — 更新状态、进度、结果、时间戳
- `get_pending()/get_running()/get_completed()/get_failed()` — 按状态筛选
- `find_interrupted(storage_path)` — 启动时扫描 Registries 找出未完成的 Session

#### SessionPersistenceManager

统一管理持久化：

```
data/
├── sessions/agents/{session_id}.json              # 单 AgentSession
├── registries/{parent_session_id}.json             # AgentSessionRegistry
├── results/{session_id}_result.json                # 执行结果
└── checkpoints/{session_id}/                       # 检查点目录
```

核心方法：

| 方法 | 功能 |
|------|------|
| `save_session()` / `load_session()` | 单个 AgentSession 持久化 |
| `save_registry()` / `load_registry()` | Registry 持久化 |
| `save_result()` / `load_result()` | 执行结果持久化 |
| `find_interrupted_sessions()` | 崩溃恢复入口，扫描 Registries |
| `cleanup_completed_session()` | 清理已完成的 Session 文件 |
| `delete_session()` | 删除 Session 文件（hibernate 清理用） |

### 2.5 会话压缩系统

#### 分层压缩策略

**文件**: `src/core/memory/compressor/history_compressor.py` (368 行)

三层压缩策略：

```
第1层 — 完整保留（最近 5 步）
  └── conversation_history[-5:] 不压缩，保持完整上下文

第2层 — 摘要压缩（中间 10-15 步）
  └── 使用 RollingSummarizer 生成 {type:"summary", content:"...", steps_covered:N}
  
第3层 — gzip 归档（更早历史）
  └── data/users/{user_id}/archives/history_{session_id}_{timestamp}.json.gz
```

压缩判断条件（任一触发）：

```python
history_len > step_limit      # max_summary_steps = 15（步数超限）
or size_kb > size_limit_kb    # 50KB（大小超限）
```

压缩结果：

```python
{
    "history": [middle_summary] + recent_full,    # 压缩后的历史
    "archived": True,                             # 是否触发归档
    "archive_path": "data/users/.../archive.gz",  # 归档路径
    "compression_ratio": 0.75                     # 压缩率
}
```

#### RollingSummarizer（滚动摘要生成器）

**文件**: `src/core/memory/compressor/rolling_summarizer.py` (325 行)

非 LLM 的轻量摘要算法：

1. `_extract_key_info()` — 提取每步的 step/state/timestamp/data
2. `_is_key_point()` — 匹配 `KEY_POINT_PATTERNS`（"市场规模""增长率"等 10 种模式）
3. `_build_summary()` — 关键点优先保留（最多 5 个），普通信息合并为步骤范围概览
4. `_truncate_summary()` — 截断到 `max_summary_length=500` 字符

支持增量更新：

```python
new_summary = summarizer.incremental_summarize(existing_summary, new_steps)
# 关键点追加，非关键点: "(+3步)"
```

#### SessionManager 压缩适配器

**文件**: `src/core/compress_adapter.py` (113 行)

将 `HistoryCompressor` 接入全局 `SessionManager`：

```python
sm = SessionManager.get_instance()
sm.set_history_compressor(SessionHistoryCompressor(
    step_limit=20,          # 步数阈值
    size_limit_kb=50,       # 大小阈值
    archive_base="data/sessions/archives"
))
```

在 `_save_to_disk()` 写入前自动触发：

```
_save_to_disk()
  └─ history_compressor.compress_if_needed(session_id, session)
       ├─ 检查 conversation_history 是否超限
       ├─ deepcopy → display_history（保留完整历史供 UI 显示）
       ├─ compress() → 替换 conversation_history（压缩后供 LLM 上下文）
       └─ 记录压缩日志（压缩率、步数变化）
```

关键特性：
- LRU 缓存 Compressor 实例（max 100 个 session）
- 线程安全（`threading.Lock` 保护）
- 失败不阻塞（`try/except`，仅 log warning）
- `display_history` 永不压缩

#### Token 预算管理

**文件**: `src/core/memory/budget/budget_manager.py` (574 行)

| 预算 | 限制 |
|------|------|
| 总预算 | 200,000 tokens |
| Layer 0 (系统基座) | 5-15 KB |
| Layer 1 (核心记忆) | < 10 KB |
| Layer 2 (工作上下文) | < 50 KB |
| Layer 3 (知识检索) | ~10 KB |
| 对话历史 | ~100 KB |

预警阈值：
- 黄 75% (150K tokens) → monitor
- 橙 85% (170K tokens) → suggest compress
- 红 95% (190K tokens) → force compress

自动压缩优先级：`conversation` > `layer2` > 其他。支持注册回调监听预警/压缩事件。

### 2.6 数据流

```
用户输入 → API → SessionManager 创建/更新 Session
  │
  ├─ SessionStreamer.push_chat_response()  → SSE → 前端展示
  │
  ├─ ExecutionEngine → 创建 Agent Agents
  │    └─ AgentSessionRegistry.register(session)
  │    └─ AgentSession.update_progress(0.5)
  │    └─ SessionStreamer.push_agent_message() → SSE → 前端进度
  │
  ├─ _save_to_disk()
  │    └─ history_compressor.compress_if_needed()
  │         ├─ display_history ← deepcopy (完整)
  │         └─ conversation_history ← compressed (摘要)
  │
  └─ session 文件 → data/sessions/{id}.json
  └─ agent session 文件 → data/sessions/agents/{id}.json
  └─ registry 文件 → data/registries/{id}.json

服务重启:
  SessionManager.recover_all(5) → 预加载最新 5 个 session
  SessionPersistenceManager.find_interrupted_sessions() → 恢复未完成的 Agent Session
```
