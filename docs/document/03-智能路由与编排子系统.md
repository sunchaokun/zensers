# 03 — 智能路由与编排子系统

> 章节定位：理解系统如何根据意图分析结果自动匹配执行路径、分解任务、编排阶段。

---

## 1. 设计目标

- 根据意图分析结果自动匹配最优执行路径
- 动态编排执行阶段，避免不必要的步骤
- 复用历史研究经验（智慧推荐）
- 支持运行时修改（暂停/追加/取消）

## 5. 执行阶段编排

DynamicPhaseOrchestrator 将任务结构转化为执行计划：

```
ExecutionPlan (PHASE_ORDER)
├── Phase 1: DATA_COLLECTION       # 数据采集（并行）
│   └── Agent: market_overview, policy_scan, ...
│
├── Phase 2: CALIBRATION           # 数据校准
│   └── 验证采集数据的完整性和一致性
│
├── Phase 3: DEEP_ANALYSIS         # 深度分析（并行）
│   └── Agent: competitive_landscape, trend_analysis, ...
│
├── Phase 4: SYNTHESIS             # 跨章节综合
│   └── Agent: cross_section_synthesis
│
└── Phase 5: REPORT_GENERATION     # 报告生成
    └── 整合各章节为完整报告
```

**执行策略**：
- 同一阶段内的 Agent 可并行执行
- 阶段间按依赖关系顺序执行
- 支持暂停/恢复/取消运行时操作

## 6. 执行引擎

### 6.1 核心功能

ExecutionEngine 是编排层的调度核心：

| 功能 | 说明 |
|------|------|
| 并行调度 | 同阶段 Agent 并行，阶段间串行 |
| 暂停/恢复 | Condition-based 等待（非轮询） |
| 取消 | 优雅取消（完成当前步骤后停止） |
| 运行时修改 | add_section / cancel_section / merge_requirement |
| 心跳监控 | 协调器 30 秒超时，进度 15 秒推送 |

### 6.2 Agent 分类

```
AgentCategory (决定 Agent 角色)
├── DATA_COLLECTION      # 数据采集
├── ANALYSIS             # 深度分析
├── SYNTHESIS            # 跨章综合
├── CALIBRATION          # 数据校准
├── REPORT_GENERATION    # 报告组装
├── QUALITY_CHECK        # 质量检查
├── DOCUMENT_GENERATION  # 文档输出
└── UNKNOWN              # 未分类
```

## 7. 结果聚合

ResultAggregator 负责将各 Agent 的结构化输出合并为统一的研究结果：

| 功能 | 策略 |
|------|------|
| 章节合并 | 按 section_details 匹配映射 |
| 去重 | 跨 Agent 的重复数据源 |
| 矛盾处理 | 以高权威度来源为准 |
| 规范化验证 | CanonicalDataRegistry.validate_section() |
