## 1. 会话管理

### 1.1 SessionManager

会话管理器是系统的持久化核心，负责长时间研究会话的创建、恢复和保存。

**核心特征**：
- 支持数十分钟到数小时的研究会话
- 会话状态自动持久化（JSON 文件），进程崩溃可恢复
- 对话历史追加式保护（防篡改）
- 启动时预加载最近 5 个会话，其余懒加载
- 写入策略：2 秒防抖 + 原子写入（temp + rename）

## 2. 对话状态机

系统定义了严格的有限状态机（FSM），共 8 个状态：

```
                    ┌──────────────┐
                    │ UNDERSTANDING │ ← 初始状态
                    └──────┬───────┘
                           │ 意图初步识别
                           ▼
                    ┌──────────────┐
              ┌─────│  CLARIFYING  │─────┐
              │     └──────┬───────┘     │
         需要更多信息 │        │ 信息充分      │ 不需澄清
              │              ▼             │
              │     ┌────────────────┐    │
              │     │FRAMEWORK_CONFIRM│◄───┘
              │     └───────┬────────┘
              │             │ 用户确认框架
              │             ▼
              │     ┌──────────────┐
              │     │  EXECUTING   │◄──────┐
              │     └──┬───┬───┬───┘       │
              │   暂停 │   │   │ 重新设计    │ 恢复
              │        ▼   │   │ 框架       │
              │  ┌────────┐│   ▼            │
              │  │PAUSED  ││  FRAMEWORK_    │
              │  └───┬────┘│  CONFIRM       │
              │      └─────┘               │
              │  取消                       │
              ▼                            │
       ┌─────────────┐                    │
       │  CANCELLED  │                    │
       └─────────────┘                    │
                                          │
              执行完成 ──▶ ┌──────────────┐
                          │  PREVIEWING  │
                          └──────┬───────┘
                                 │ 用户确认
                                 ▼
                          ┌──────────────┐
                          │  COMPLETED   │
                          └──────────────┘
```

**关键转换规则**：
- `UNDERSTANDING → CLARIFYING`：LLM 判断信息不足以确定研究框架
- `CLARIFYING → FRAMEWORK_CONFIRM`：readiness_score ≥ SUFFICIENT 阈值
- `FRAMEWORK_CONFIRM → EXECUTING`：用户确认研究框架
- `EXECUTING → PAUSED → EXECUTING`：暂停/恢复循环（保留上下文）
- `EXECUTING → FRAMEWORK_CONFIRM`：执行中重新设计框架
- `PREVIEWING → COMPLETED`：用户确认报告终稿

## 3. 意图分析 (Intent Analysis)

### 3.1 意图分类体系

```
IntentType
├── RESEARCH        # 市场分析、数据收集
├── IMPLEMENTATION  # 报告生成、内容产出
├── INVESTIGATION   # 问题诊断、根因分析
├── EVALUATION      # 质量检查、对比评估
├── FIX             # 错误修正、内容修订
├── OPEN_ENDED      # 开放性探索研究
└── CLARIFICATION   # 需要用户进一步输入

TaskComplexity
├── TRIVIAL  → 简单查询
├── SINGLE   → 单一任务
├── MULTI    → 多任务组合
└── COMPLEX  → 复杂研究项目
```

### 3.2 研究类型体系（15 种）

```
ResearchType
├── 基础研究
│   ├── INDUSTRY_RESEARCH      # 行业研究
│   ├── BRAND_RESEARCH         # 品牌研究
│   ├── COMPANY_RESEARCH       # 企业研究
│   ├── CONSUMER_RESEARCH      # 消费者研究
│   └── COMPETITIVE_ANALYSIS   # 竞争分析
├── 专项研究
│   ├── MARKET_SIZING          # 市场规模测算
│   ├── POLICY_ANALYSIS        # 政策分析
│   └── TECHNOLOGY_RESEARCH    # 技术研究
├── 数据采集
│   ├── SURVEY                 # 问卷调查
│   ├── INTERVIEW              # 深度访谈
│   └── OBSERVATION            # 实地观察
└── 分析框架
    ├── DATA_ANALYSIS          # 数据分析
    ├── SWOT_ANALYSIS          # SWOT分析
    ├── PESTEL_ANALYSIS        # PESTEL分析
    └── PORTER_ANALYSIS        # 波特五力分析
```

### 3.3 语义意图分析流程

```
用户输入
    │
    ▼
SemanticIntentAnalyzer
    │
    ├── ① 首选：LLM 深度语义分析
    │   分析 5 个维度：
    │   • 显式意图 — 用户明确表达的需求
    │   • 隐式意图 — 未明说但必要的步骤
    │   • 复合意图 — 多个独立子任务
    │   • 歧义检测 — 是否需要进一步澄清
    │   • 复杂度评估 — 基于数据需求和推理深度
    │
    ├── ② 降级：关键词匹配
    │   keyword_mappings.yaml → 关键词匹配
    │   当 LLM 不可用时自动降级
    │
    └── 输出：DeepIntentResult（31 个字段）
```

### 3.4 DeepIntentResult 数据结构

| 字段组 | 关键字段 | 说明 |
|--------|---------|------|
| 核心意图 | primary_intent, intent_confidence | 主意图及置信度 |
| 研究类型 | research_types, primary/secondary | 研究类型及主次 |
| 任务范围 | task_scope, complexity, aspect_count | 范围、复杂度量化 |
| 上下文 | domain_context, hidden_requirements | 领域信息、隐含需求 |
| 复合意图 | is_composite, sub_intents | 子意图列表、编排策略 |
| 执行规格 | section_data_specs, recommended_skills | 章节数据规格、技能推荐 |

### 3.5 增量分析机制

系统支持 `analyze_incremental()`，适用于对话中用户追加信息或修改需求：

- **意图融合**：新分析结果与已有意图合并，置信度低时保留原有判断
- **跳过阶段判定**：根据已有意图状态决定哪些执行阶段可以跳过
- **内容锁管理**：`ContentLockManager` 防止对共享章节的并发编辑冲突

## 4. DialogueIntentState（对话意图状态）

在多轮对话中持续积累和更新意图信息：

```python
class DialogueIntentState:
    topic_hint: str                    # 主题提示
    confirmed_aspects: List[str]       # 已确认的研究方面
    pending_questions: List[str]       # 待澄清问题
    hidden_requirements: List[str]     # 隐含需求
    domain_context: Dict[str, Any]     # 领域上下文
    is_composite: bool                 # 是否复合意图
    sub_intents: List[SubIntent]       # 子意图列表
    readiness_score: float             # 就绪度分数 (0.0-1.0)
    readiness_level: ReadinessLevel    # 就绪度等级
    clarification_count: int           # 澄清次数
```

更新机制：
- `update_from_response()`：从 LLM 对话结果提取更新
- `merge_from_analysis()`：与 DeepIntentResult 置信度融合
