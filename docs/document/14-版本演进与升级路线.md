# 14 — 版本演进与升级路线

> 章节定位：从宏观视角回顾系统演进历史，并展望未来升级方向。

---

## 1. 演进历史

### 1.1 版本里程碑

| 版本 | 时间 | 核心变化 | 代码量 |
|------|------|----------|--------|
| v0.1 | 初始期 | 最小可行性系统 + 7 层架构 | ~5K |
| v0.2 | 功能期 | Agent 系统 + Skill 系统 + MCP | ~20K |
| v0.3 | 质量期 | 质量控制 + 知识管理 + SSE | ~50K |
| v0.4 | 设计期 | 大量设计文档 + 基础设施优化 | ~90K |
| v0.5 | 当前 | 数据采集 + 测试体系 + 设计重构 | ~132K |

### 1.2 关键演进决策

**为什么从单任务到多 Agent**：
- 前期：一个 Agent 做所有事情 → LLM 上下文窗口限制，任务切换开销大
- 现在：Orchestrator + Decomposer + 多个 Specialized Agent → 专业化、并行化

**为什么设计优先于编码**（v0.4 到 v0.5）：
- 快速编码导致多处架构不一致（如双 Agent 系统、15 处 Skill 注册点）
- 多轮内部 retro 后达成共识：重大变更必须有设计文档
- 当前状态：设计文档库 70+ 份，但部分设计方案未实施
