# 01 — 系统整体架构

> 章节定位：从全局视角理解系统的分层架构、数据流转和模块组织。

---

## 1. 七层架构

系统采用严格的七层分层架构，上层依赖下层，下层对上层无感知：

```
┌─────────────────────────────────────────────────────────────┐
│ Layer 7: 应用层 (Application)                       │
│   CLI / Web API / FastAPI 端点                              │
├─────────────────────────────────────────────────────────────┤
│ Layer 6: 编排层 (Orchestration)                     │
│   ResearchOrchestrator / DynamicAgentFactory / 执行引擎         │
├─────────────────────────────────────────────────────────────┤
│ Layer 5: Agent层 (Agent)                           │
│   FixedAgents / DynamicAgents / Session / 通信               │
├─────────────────────────────────────────────────────────────┤
│ Layer 4: 能力层 (Capability)                        │
│   Skills / MCP Tools / Converters                          │
├─────────────────────────────────────────────────────────────┤
│ Layer 3: 记忆层 (Memory)                            │
│   CoreMemory / SessionMemory / KnowledgeBank                │
├─────────────────────────────────────────────────────────────┤
│ Layer 2: 通信层 (Communication)                     │
│   MessageBus / SharedMemory / ResultCollector                │
│   SessionStreamer (会话级SSE推送)                             │
├─────────────────────────────────────────────────────────────┤
│ Layer 1: 存储层 (Storage)                           │
│   TaskStorage / WAL / ResearchResultStore                   │
├─────────────────────────────────────────────────────────────┤
│ Layer 0: 约束层 (Constraint)                        │
│   SourceWhitelist / FactTracer / CrossValidator            │
└─────────────────────────────────────────────────────────────┘
```

各层职责：

- **Layer 7 应用层**：用户交互入口。提供 CLI 命令行和 RESTful API 接口，SSE 实时推送进度。
- **Layer 6 编排层**：核心调度中心。接收用户需求，调度 Agent 团队，协调执行流程。
- **Layer 5 Agent层**：执行实体。固定 Agent 处理核心能力，动态 Agent 按需创建。
- **Layer 4 能力层**：可插拔的能力单元。Skill 是内部能力，MCP Tool 是外部能力。
- **Layer 3 记忆层**：知识存储与检索。从高频 CoreMemory 到全量 KnowledgeBank。
- **Layer 2 通信层**：Agent 间协作基础设施 + 前端实时推送。消息发布/订阅（MessageBus）、共享状态（SharedMemory）、执行结果汇聚（ResultCollector）、会话级 SSE 推送（SessionStreamer）。
- **Layer 1 存储层**：数据持久化。原子写入 + WAL 崩溃恢复。
- **Layer 0 约束层**：质量控制。源白名单、事实追踪、交叉验证。

## 2. 核心数据流

完整的端到端数据流转：

```
用户输入
  │
  ▼
┌──────────────┐    ┌──────────────────┐    ┌──────────────────┐
│  会话管理     │───▶│  对话状态机       │───▶│  LLM对话循环      │
│  SessionMgr  │    │  StateMachine    │    │  + 工具调用       │
└──────────────┘    └──────────────────┘    └──────────────────┘
                                                    │
                                            意图明确 │
                                                    ▼
┌──────────────┐    ┌──────────────────┐    ┌──────────────────┐
│  智能路由     │───▶│  任务分解         │───▶│  Agent编排执行    │
│  RoutingAdpt │    │  Decomposition   │    │  ExecutionEngine │
└──────────────┘    └──────────────────┘    └──────────────────┘
                                                    │
                                            执行完成 │
                                                    ▼
┌──────────────┐    ┌──────────────────┐    ┌──────────────────┐
│  结果聚合     │───▶│  预览生成         │───▶│  质量检查+修复    │
│  Aggregator  │    │  PreviewGen      │    │  QualityCheck    │
└──────────────┘    └──────────────────┘    └──────────────────┘
                                                    │
                                            用户确认 │
                                                    ▼
                                          ┌──────────────────┐
                                          │  文档导出+知识沉淀 │
                                          │  Export+Knowledge │
                                          └──────────────────┘
```

核心原则：**研究框架驱动** — 在数据采集前先生成统一的研究框架（核心问题 + 维度划分 + 逻辑链），确保各章节的分析方向一致。

## 5. 关键设计原则

| 原则 | 说明 |
|------|------|
| **约束优先** | 数据进入系统前先验证，防止污染下游 |
| **渐进存储** | 热→冷分层存储策略，高频数据快速访问 |
| **步骤保存** | 每次状态变更立即持久化，崩溃恢复不丢数据 |
| **依赖反转** | 面向接口编程，抽象依赖，便于测试 |
| **单一职责** | 每个模块只有一项核心职责 |
| **Master不执行** | 编排器只调度不处理，避免逻辑膨胀 |
